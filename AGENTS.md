# AGENTS.md — instructions for AI agents working on this repository

Read this before making any change. For the full technical map, see
[ARCHITECTURE.md](ARCHITECTURE.md). For user-facing behaviour, see [README.md](README.md).

---

## 1. What this project is

**Data Workbench Console** — a local-first, deliberately restrictive SQL operator console for
Microsoft Fabric SQL endpoints, Fabric Lakehouse SQL endpoints and SQL Server. Next.js 15 +
React 19 shell, `mssql`/Tedious for data access, flat files for persistence, no database of
its own. It ships as a Windows desktop app: a hidden server bound to `127.0.0.1`, launched
from a Desktop shortcut, self-updating over Git.

Its selling point is **execution control**, not convenience. Reads run directly; writes are
classified, previewed in a rolled-back transaction, and released only against a single-use
confirmation token. This is the product, not an obstacle.

Proprietary and closed. Do not add license headers, "generated by" banners, or attribution
notices to source files.

## 2. The five things that will trip you up

1. **The UI is not React.** React emits a static DOM skeleton once
   ([app/components/workbench-shell.js](app/components/workbench-shell.js) — 873 lines of JSX,
   zero state). The application is [public/console-core.js](public/console-core.js): 7060 lines
   in one closure, driving the DOM with `$('id')`, `innerHTML` and `onclick`. Do not "modernize"
   this into components, hooks or a state library. Follow the existing pattern.

2. **`id` attributes are a contract.** `console-core.js` and
   [scripts/ui-smoke.mjs](scripts/ui-smoke.mjs) both address the DOM by id. Renaming an id in
   the shell silently disables a feature and breaks the smoke test. If you must rename, update
   the shell, `console-core.js`, `TOOLTIP_DESCRIPTIONS`, `ui-smoke.mjs` and
   `responsive-audit.mjs` in the same change.

3. **`lib/server/sql-classifier.js` is safety-critical.** It is pure, does no I/O, and decides
   whether a statement runs directly, gets previewed, or demands a typed acknowledgement. Any
   behavioural edit here must land with new cases in
   [scripts/sql-classifier.test.mjs](scripts/sql-classifier.test.mjs). Never widen the read
   path. Never remove a confirmation requirement without an explicit instruction to do so.

4. **Layout is computed in JavaScript, not CSS.** `getLayoutMode()` measures real widths and
   writes `data-layout-mode` / `data-workspace-mode` / `data-studio-mode` /
   `data-procedure-layout-mode` onto `.app-shell`; CSS reacts to those attributes. Adding a
   media/container query that overrides a JS-driven grid template is exactly the bug fixed in
   1.4.19 and 1.4.22. Prefer changing the JS thresholds.

5. **Everything is escaped by hand.** There is no framework escaping in the client. Every
   interpolated value goes through `esc()`
   ([console-core.js:422](public/console-core.js#L422)). Forgetting it is an XSS bug.

## 3. Commands

```bash
npm ci                    # install from the lockfile
npm run dev               # dev server on :3000
npm run build             # production build (required before ui-smoke)
npm run start             # production server, bound to 127.0.0.1
npm run clean             # remove .next

npm run test:server       # fast: lib/server units, temp dirs, no server
npm run test:routes       # boots next start on :3120, HTTP contracts, no DB
npm run responsive:audit  # Playwright, 16 widths × 2 routes + themes, writes screenshots

npm run verify            # clean, build, classifier, metadata, smoke, ui-smoke, responsive
npm run verify:release    # + server-unit, route-contract, npm ls, npm audit, diagnostics
```

There is **no test framework and no linter config**. Suites are plain Node scripts using
`node:assert/strict` that exit non-zero on failure. Do not introduce Jest, Vitest, ESLint or
Prettier unless explicitly asked.

Ports in use: app `3000`, smoke `3100`, route-contract `3120`, responsive audit `3210`.

## 4. Where to make a change

| Task | Files |
| --- | --- |
| Query safety, classification, row capping | `lib/server/sql-classifier.js` + its test |
| Catalog reads, DDL generation, source fallbacks | `lib/server/sql-metadata.js` + its test |
| Route behaviour, validation, audit emission | `lib/server/db-interface.js` |
| Middleware, CSRF, rate limiting, cookies | `lib/server/next-handler.js` |
| Source types, auth modes, pooling | `lib/server/source-config.js` |
| A new `.env` setting | `lib/server/env-settings-store.js` **and** `.env.example` |
| Any UI behaviour | `public/console-core.js` |
| Any UI markup | `app/components/workbench-shell.js` |
| Layout arrangement | `getLayoutMode()`/`applyPanelLayout()` in `console-core.js`, then `app/workbench.css` |
| Themes, tokens, control primitives | `app/theme.css` |
| Component styling | `app/workbench.css` |
| Built-in user guides | `app/docs/sql-studio/page.js`, `app/docs/procedure-runner/page.js` |
| Launcher / updater | `Start Data Workbench.ps1`, `scripts/apply-update.ps1`, `launcher-loading.html` |

API route files under `app/api/` are 7–20 line adapters. Keep them that way — logic belongs in
`lib/server/`.

## 5. Conventions to match

- **ESM only.** `"type": "module"`; scripts use `.mjs`. No `require`, no CommonJS.
- **No TypeScript.** Do not add type annotations, `.d.ts` files or JSDoc type generics beyond
  the light `@param`/`@returns` style already present in `sql-classifier.js`.
- 2-space indent, single quotes, semicolons, no trailing commas in multi-line literals.
- `function` declarations at module/closure top level; arrow functions for callbacks.
- Defensive coercion is the house style: `String(value || '')`, `Number(x || 0)`,
  `Array.isArray(x) ? x : []`, optional chaining and `??` throughout. Match it.
- Errors carry `error.httpStatus` for the middleware to map. Throw those, don't return them.
- **Comments explain *why*, never *what*.** The existing non-obvious comments (atomic token
  claim, `git reset --hard` rationale, audit rewrite-vs-append, CSV formula escaping, BIGINT
  identity precision) are the model. Do not add narration.
- Client storage keys are versioned (`…V1`, `…V2`, `…V3`). Bump the suffix when a shape
  changes incompatibly rather than writing migration code.
- Audit `detail` fields use `compactQueryPreview` / `compactProcedurePreview`. Never log
  parameter *values*, passwords or secrets.

## 6. Definition of done

Before you report a change complete:

- [ ] `npm run build` succeeds.
- [ ] Safety-model change → new cases in `scripts/sql-classifier.test.mjs`, suite passes.
- [ ] `lib/server` change → `npm run test:server` passes.
- [ ] Route contract change → `npm run test:routes` passes.
- [ ] UI change → `node scripts/ui-smoke.mjs` passes (**needs a fresh build first**) and a
      wiring assertion was added for any new control.
- [ ] Layout/CSS change → `npm run responsive:audit` passes with no new entries in
      `responsive-audit/responsive-audit.json`.
- [ ] New `.env` key → present in `.env.example` (enforced by `server-unit.test.mjs`),
      documented in `README.md`, and in the docs pages if user-visible.
- [ ] New user-visible behaviour → documented in `README.md` and the relevant `app/docs` page.
- [ ] `CHANGELOG.md` entry added under a new version heading (see §7).
- [ ] No runtime files staged: `.env`, `.data/`, `data/`, `audit-log*.ndjson`,
      `responsive-audit/`. `scripts/release-diagnostics.mjs` fails the release if any are tracked.

## 7. Releasing

Version lives in **three** places that must agree:

1. `package.json` → `version`
2. `package-lock.json` → `packages[""].version` (asserted by `release-diagnostics.mjs`)
3. `README.md` → the `Current app version:` line

Then add a `CHANGELOG.md` entry at the top following the existing format —
`## <version> - <YYYY-MM-DD>`, a one-line summary, then `### Added` / `### Changed` /
`### Fixed` / `### Security` / `### Verification` sections as applicable. Entries describe
*user-visible effect and root cause*, not file diffs.

Finally run `npm run verify:release` and work through
[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).

Update the version only when asked, or when the change is being released. Do not bump it for
every edit.

## 8. Do not

- Do not commit or push unless explicitly asked. If asked while on `main`, branch first.
- Do not read, print, copy or commit `.env`. A local `.env` exists and may hold a real
  `AZURE_CLIENT_SECRET` and database credentials. Use `.env.example` as the reference instead.
- Do not touch `.data/`, `data/`, `audit-log*.ndjson` or `responsive-audit/` — runtime state.
- Do not run `npm run verify:live` / `scripts/live-smoke.mjs`. It connects to a real database
  and requires two explicit opt-in environment variables.
- Do not point any test or example at a host or database matching `prod`, `prd`, `production`
  or `live`.
- Do not weaken the safety model: no new statement types on the read path, no removed
  confirmation requirements, no bypass flags, no "skip preview" options.
- Do not unblock `GO`. It is a client-tool separator that Tedious genuinely cannot execute.
- Do not add dependencies casually. The runtime list is deliberately five packages; `npm audit
  --omit=dev` must stay clean and `overrides` in `package.json` exists to keep it that way.
- Do not add a client bundler, framework or state library for `public/*.js`. Those files are
  served verbatim to the browser as plain ES5/ES2020-compatible script.
- Do not reformat files you are not otherwise changing.

## 9. Windows notes

This project is developed and shipped on Windows; the launcher, updater and file-replace
retry logic all assume it.

- File replacement uses write-to-temp then `rename`, with a retry loop for `EPERM`/`EACCES`
  because Windows holds locks briefly. Match that pattern in any new store
  (see `confirmation-store.js` / `audit-store.js`).
- Paths in PowerShell scripts use `-LiteralPath` and `Join-Path`. Keep it.
- `.gitattributes` normalizes the repo to LF. Do not commit CRLF — it breaks the updater's
  clean-tree assumptions on other machines.
- Log output goes to `.data/logs/` (`data-workbench-launcher.log`, `data-workbench-server.log`,
  `data-workbench-update.log`), never the project root.

## 10. Known issues

**No open defects are currently tracked.** The ones found in the 1.4.25/1.4.26 audit are fixed;
`CHANGELOG.md` has the history.

If you find a defect and are not fixing it in the same change, open a `BUGS.md` at the
repository root and follow this convention:

- **Reproduce it first.** Paste the reproduction (a command, or exact steps) into the entry.
  Never file unverified suspicions.
- One entry per defect: ID, severity, location, symptom, reproduction, root cause, suggested
  fix, and the specific regression test to add. Never recycle an ID.
- Severity `decision` means it needs the maintainer's intent before any code change — ask, do
  not guess.
- Do not fix an entry incidentally while doing unrelated work. Fix it as its own change with
  the named regression test, or leave it alone.
- When you fix one: add the test, record it in `CHANGELOG.md`, then **delete the entry**
  (including its index row). Do not mark it done or move it to a "fixed" section. When the file
  is empty, delete the file and update the pointers in `ARCHITECTURE.md §21` and here.
- If an entry turns out to be intended behaviour, move the explanation into
  [ARCHITECTURE.md §21](ARCHITECTURE.md#21-known-issues-and-intentional-oddities) instead.

Conversely, several things look like bugs but are deliberate — `GO` blocking,
`git reset --hard` in the updater, the full audit-log rewrite on every entry, treating a
fast-exiting updater launcher as success, and the textarea-plus-backdrop editor. Read
[ARCHITECTURE.md §21](ARCHITECTURE.md#21-known-issues-and-intentional-oddities) before
changing any of them.
